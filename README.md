> macOS 缓存清理 Agent。它吃东西之前，会先洗一洗。

苹果的固态硬盘是焊死在主板上的，升一档 512G，加价 **¥1500**。

这个 skill 第一次出手，从我的机器里清出了 **135+ GB** 缓存，一晚，零翻车。

被缓存塞满的机器，人最终会做什么？换更大的硬盘，多付那一档升配钱。小浣熊省下的就是这笔：**它大概是你的 agent 里最值钱的一个 skill，¥1500 起。**

## 缘起

我用开源工具 [Mole](https://github.com/tw93/Mole) 扫了一下硬盘，它找出了几个很大的文件夹，每个都几个 G。

但是，删不删呢？

飞书的缓存目录里，一部分是文档缓存删了没事，另一部分是登录态删了要重新扫码。Chrome 的 Service Worker 删了没事，旁边的 IndexedDB 删了网页应用数据就没了。同一个目录里，一半是垃圾，一半是状态。扫帚能扫出大小，扫不出答案。

于是让 AI 来做判断。这个 skill 就是那份判断本身：每一类缓存在哪、能删到什么程度、删之前要先退出谁、删完谁会重新下载。第一次实战，一晚清出 **135+ GB**，零翻车。

## 为什么是一只浣熊

浣熊是自然界唯一在吃东西前先把食物洗一洗的动物。

它不是不吃，是不瞎吃。

大多数清理工具的逻辑是"扫全盘，把大的列出来让你勾"。但 macOS 真正的问题是：**大 ≠ 垃圾，垃圾 ≠ 大**。

- 飞书看文档攒下 42G 缓存，藏在 `LarkShell/aha` 深处，Finder 看不见
- Chrome 的 Service Worker 吃掉 30G，但旁边的 IndexedDB 删了会丢网页应用数据
- Telegram 的媒体缓存能涨到 100G，官方 issue 里骂了八年没修
- `~/.cache/uv` 静悄悄吃掉 56G

**小浣熊的灵魂不是删东西，是分得清什么能删。** 先洗，再吃。

## 它只做一件事：缓存

不做应用卸载，不做后台管理，不做系统优化——那些是 [Mole](https://github.com/tw93/Mole) 🐹 的活儿，一把好扫帚，开源免费。

小浣熊只做缓存，但做到底：**知道每一类缓存在哪、能删到什么程度、删之前要先退出谁、删完谁会重新下载。** 这份判断写在一份持续维护的缓存地图里（`references/cache-map.md`），每条路径标注三级安全等级：

- ✅ **安全**：`~/.cache/uv`、浏览器 Service Worker、Telegram 媒体缓存……
- ⚠️ **注意**：飞书 `LarkShell/aha`（只删 `profile_explorer`，`profile_main` 有登录态）、微信（建议走 app 内清理）……
- 🚫 **别碰**：消息数据库、钥匙串、任何带"状态"的目录

地图上没有的路径怎么办？先认清它是什么，查官方文档，认清之前一个字节都不动。

## 安全设计

| 原则 | 说明 |
|---|---|
| 默认只读 | 第一轮体检不删任何东西，报告先行 |
| 先认清再删 | 缓存地图上没有的路径，查清楚之前不动 |
| 可恢复优先 | 能进废纸篓的绝不直接删除 |
| 状态神圣 | 登录态、消息数据库、钥匙串永远不碰 |
| 运行中不动刀 | app 正在跑就先退出，避免边删边重建 |
| sudo 分离 | 系统级删除生成命令，由用户亲自执行 |

## 安装

把本仓库放进你的 agent skills 目录：

```bash
git clone https://github.com/orange2ai/disk-raccoon ~/.claude/skills/disk-raccoon
```

兼容支持 SKILL.md 协议的 agent（Claude Code、Cola 等）。

## 用法

对 agent 说：

- "帮我做个缓存体检"
- "磁盘满了，看看什么缓存能清"
- "Chrome 怎么占了 60G？"

## 实战记录

| 缓存 | 释放 |
|---|---|
| `~/.cache/uv`（Python 包缓存） | ~56G |
| Chrome Service Worker + ChromeDebug 残留 | ~51G |
| 飞书 `LarkShell/aha` 文档缓存 | ~38G |
| **合计** | **135+ GB** |

按苹果官方升配价（512G 一档，¥1500），这 135G 就是 **小半档的闪存钱**。如果你的盘是被缓存通到升配的，它帮你省下的就是整个一档。
